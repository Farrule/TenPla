# 要件定義・基本設計書：PDF-Excel自動転記システム

## 1. システム概要・目的

### 1.1 背景と目的

取引先ごとにレイアウトや表記揺れが存在するPDF帳票（請求書、納品書等）から必要なデータ項目を抽出し、社内規定の統一フォーマット（Excelファイル）へ自動転記するシステムを構築する。

### 1.2 コアコンセプト

- **フォーマットの外部定義化**：取引先ごとの抽出仕様を設定ファイル（JSON）として分離し、コード修正なしで定義を切り替え可能にする。
- **ユーザー主導のメンテナンス**：専門知識のない一般ユーザーがGUI画面から直感的にフォーマットの新規登録・修正・検証を行える仕組みを提供する。
- **段階的なアーキテクチャ拡張**：初期フェーズはローカル設定ファイルを参照する構成で開発を進め、将来的な中央管理（ファイルサーバー化）や単一実行ファイル（Tauriによる `.exe` 化）へ手戻りなく移行可能な疎結合設計とする。

## 2. 技術スタック・選定理由

| **レイヤー**         | **採用技術**                        | **選定理由**                                                                                                                    |
| -------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **Backend**          | **Python 3.10〜3.12 / FastAPI**     | 帳票解析（`pdfplumber`）およびExcel操作（`openpyxl`）のエコシステムが最も充実しており、高速なAPI開発が可能なため。              |
| **Frontend**         | **Vite + React (TypeScript)**       | 高速なSPA開発が可能。Next.js特有のSSR制約を回避し、静的HTML出力（`dist`）をそのままTauriのシェルへ流用できるため。              |
| **CSS / UI**         | **Tailwind CSS**（推奨: shadcn/ui） | 保守性が高く、分割画面やプレビューUIを素早く構築できるため。                                                                    |
| **Packaging (将来)** | **Tauri (Rust / WebView2)**         | Electronと比較してメモリ消費が極めて小さく、Windows環境向けに軽量な単一バイナリ（`.exe`）およびインストーラーを生成できるため。 |

### 3.2 抽出設定データ構造（JSONスキーマ仕様）

設定ファイルはローカルの `backend/formats/{company_id}.json` に配置し、以下の仕様で管理する。

JSON

```
{
  "company_id": "company_a",
  "company_name": "株式会社サンプル商事",
  "rules": [
    {
      "field_name": "請求日",
      "excel_cell": "B2",
      "method": "regex",
      "pattern": "請求日[：:\\s]*([0-9]{4}/[0-9]{1,2}/[0-9]{1,2})"
    },
    {
      "field_name": "合計金額",
      "excel_cell": "D2",
      "method": "keyword_after",
      "keyword": "合計金額",
      "regex_filter": "([0-9,]+)円?"
    },
    {
      "field_name": "明細テーブル",
      "excel_start_cell": "A10",
      "method": "table",
      "table_index": 0
    }
  ]
}
```

- **抽出方式（`method`）の種類**:
  - `keyword_after`: 特定キーワードの右隣または下位の文字列を取得。
  - `regex`: 正規表現パターンによるマッチング（日付・金額等）。
  - `table`: PDF内の指定インデックスの表構造をそのまま取得。
  - `bbox`（任意）: PDF内の絶対座標（X, Y, 幅, 高さ）による指定領域抽出。

## 4. フロントエンド画面仕様

### 4.1 画面1：メイン画面（変換・エクスポート）

日々の定常業務で利用する画面。誤転記を防ぐための事前確認ステップを設ける。

1. **会社（フォーマット）選択**:
   - `GET /api/formats` から取得したリストをドロップダウン表示。
2. **ファイル投入領域**:
   - PDFファイルのドラッグ＆ドロップおよびファイルダイアログ選択。
3. **抽出結果プレビュー（テーブル表示）**:
   - バックエンドで抽出したデータを即時Excel化せず、画面上のテーブルに「項目名」「抽出された値」を行列で表示。
   - 読み取りミスがあった場合、画面上でテキストの手動修正を可能にする。
4. **Excel出力アクション**:
   - 「Excelファイルをダウンロード」ボタン押下により、テンプレートへ流し込まれた `.xlsx` をストリーミング取得。

### 4.2 画面2：フォーマット設定画面（ルールエディタ）

新規取引先の追加やレイアウト変更時に利用する2カラム構成の画面。

```
+------------------------------------+------------------------------------+
| 【左側: PDFプレビュー領域】        | 【右側: 転記・マッピング設定領域】 |
|                                    |                                    |
| [サンプルPDFアップロード]          | 会社ID: [ company_a ]              |
| [拡大/縮小] [ページ切り替え]       | 会社名: [ 株式会社サンプル商事   ] |
| +--------------------------------+ | ---------------------------------- |
| |                                | | ■ 抽出ルール設定一覧               |
| | 請求書                         | | 1. 項目名: [ 請求日   ]          |
| | 請求日: 2026/09/01             | |    Excelセル: [ B2 ]             |
| |                                | |    抽出方式:  [ キーワード右隣 ▼]|
| | 合計金額: ¥120,000             | |    キーワード: [ 請求日 ]        |
| |                                | | ---------------------------------- |
| | +----+------+----+             | | 2. 項目名: [ 明細テーブル ]        |
| | |品名| 数量 |金額|             | |    開始セル:  [ A10 ]            |
| | +----+------+----+             | |    抽出方式:  [ 表（テーブル）  ▼]|
| | |A品 |   1  |5000|             | |    対象テーブル: [ 1番目の表 ▼]   |
| | +----+------+----+             | |                                    |
| +--------------------------------+ | [+ ルールを追加]                   |
|                                    |                                    |
|                                    | [テスト抽出実行]    [設定を保存]   |
+------------------------------------+------------------------------------+
```

- **左ペイン（PDFプレビュー）**:
  - `react-pdf` を用いてサンプルPDFを描画。
  - テキスト選択イベントを拾い、クリックした文字列を右ペインの「キーワード」入力欄に直接流し込むUI補助を実装。
- **右ペイン（ルールビルダー）**:
  - React Hook Form を用いて動的に設定行を増減（`useFieldArray`）。
  - 抽出方式に応じて入力項目（キーワード／正規表現／テーブル番号）を動的に切り替え。
- **テスト抽出機能**:
  - 保存前に、現在のルール定義をメモリ上でサンプルPDFに対して実行し、抽出成否を画面上でテスト可能にする。
- **保存**:
  - `POST /api/formats` をコールし、ローカルのJSONファイルを新規作成・上書き保存。

## 5. APIインターフェース仕様（FastAPI）

| **メソッド** | **パス**            | **役割**                       | **リクエスト**                          | **レスポンス**                                                      |
| ------------ | ------------------- | ------------------------------ | --------------------------------------- | ------------------------------------------------------------------- |
| `GET`        | `/api/formats`      | 登録済みフォーマット一覧取得   | なし                                    | `[ { company_id, company_name } ]`                                  |
| `GET`        | `/api/formats/{id}` | 特定フォーマットの詳細定義取得 | パスパラメータ                          | `CompanyFormat` (JSON)                                              |
| `POST`       | `/api/formats`      | フォーマットの新規作成・更新   | `CompanyFormat` (JSON)                  | `{ status: "saved" }`                                               |
| `POST`       | `/api/preview`      | サンプルPDFに対するテスト抽出  | `multipart/form-data` (pdf, rules_json) | `{ extracted_data: { [key]: value } }`                              |
| `POST`       | `/api/convert`      | 本番変換とExcelファイルの返却  | `multipart/form-data` (pdf, company_id) | `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` |

## 6. 動作・実行環境要件

### 6.1 開発環境（開発者PC）

- **OS**: Windows 10 / 11（macOS / Linuxでの開発も可）
- **Node.js**: 18.x または 20.x (LTS)
- **Python**: 3.10 〜 3.12
- **（Tauriビルド時のみ必要）**: Rust (`rustup`), Microsoft Visual Studio C++ Build Tools

### 6.2 運用環境（エンドユーザーPC）

- **Tauriデスクトップアプリ化（推奨形態）**:
  - ユーザーPCへのNode.js / Pythonのインストールは一切不要。
  - Python処理系は `PyInstaller` でバイナリ化し、TauriのSidecarとして同梱した単一インストーラー（`.msi` / `.exe`）を配布。
  - OS標準の Microsoft Edge WebView2 ランタイムを利用。
- **社内Webサーバー形態**:
  - 社内PC1台をサーバー（FastAPI + 静的ビルド配信）として稼働させる場合、利用者はChromeやEdge等のWebブラウザのみで利用可能。

## 7. 今後のマイルストーン

1. **フェーズ1（コア検証・CLI）**: `pdfplumber` で実サンプル数社のPDFから狙ったデータ・表が安定して抜けるか検証。
2. **フェーズ2（Backend API実装）**: FastAPIによるフォーマット管理・抽出・Excel書き込みAPIの実装。
3. **フェーズ3（Frontend UI実装）**: Vite + React による変換プレビュー画面およびフォーマット設定画面の作成・結合。
4. **フェーズ4（Tauriデスクトップ化）**: フロントエンドの静的ビルドとPythonバイナリの同梱、Windowsインストーラー生成。
